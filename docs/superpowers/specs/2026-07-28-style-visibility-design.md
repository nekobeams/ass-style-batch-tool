# 樣式可見化與流程優化 設計文件

日期:2026-07-28
狀態:已與使用者確認,待寫實作計畫

## 問題

使用者實測後提出的三個問題,底層是同一件事:**工具握有的資訊沒有給使用者看見。**

1. **看不到樣式名稱。**「目標 Style」是自由輸入的逗號分隔文字框,但工具不告訴你這批檔案裡到底有哪些樣式名。使用者必須開 Subtitle Edit 查完再回來填。填錯的回饋是整批 `skipped`(訊息寫「找不到目標 Style」)——得先跑失敗一輪才知道要去別的軟體查,再回來重填。**一個工具讓你為了填它自己最重要的欄位而必須開另一個軟體,這是流程斷裂。**

2. **開啟時資料夾路徑像殘留。** 設定持久化只還原路徑、不掃描,所以使用者看到路徑卻看到空表格,感覺像沒清乾淨的殘留,而不是「回到上次的位置」。而且這與使用者先前明確要求的「選資料夾就自動載入」不一致。

3. **跨分頁來回。** 樣式編輯器在「樣式與預覽」分頁,掃描與執行在「字幕檔 / MKV / 封裝」分頁。樣式名稱是在 A 分頁發現、拿到 B 分頁使用。

## 使用情境(使用者確認)

一季之內目標樣式名稱**全季一致**,使用者只是不知道它叫什麼(`Default` 還是 `CHT`)。

**因此不需要逐檔覆蓋率表格。** 一份簡單清單即可;逐檔統計降級為「僅在偵測到不一致時才出聲」,平常不佔版面。

## 設計

### 1. 「目標 Style」搬到工作分頁側欄

從樣式編輯器移到字幕檔 / MKV / 封裝三個分頁的設定側欄,緊鄰掃描結果——發現和使用在同一個畫面。

**存放位置:每個工作分頁各自記住自己的勾選**,跟該分頁的資料夾路徑一起存在 QSettings。

理由:三個分頁常常對著不同資料夾,共用一份勾選會互相打架。而且這個欄位回答的是「這批要改哪個樣式」,與 profile 描述的「改成什麼樣子」性質不同——換一季就可能要改它,但字型顏色通常不動。

**向下相容:** profile 的 `target_style_names` 鍵保留於檔案格式中,降級為「首次使用時的預設建議值」。樣式編輯器不再顯示此欄位,存檔時原樣保留不修改。舊 profile 帶來的名稱會被當成預選值。

**封裝分頁的條件顯示:** 該分頁可選「直接封裝原字幕」或「先套用樣式再封裝」。選直接封裝時不需要指定目標樣式,樣式清單隨該模式一起隱藏,與既有的 `scale_panel` 顯示/隱藏行為一致。

### 2. 側欄樣式清單

掃描後自動填入可勾選清單。

**核心不變式:profile 帶來、但這批檔案裡不存在的樣式名,絕對不自動取消勾選。** 它照常顯示並標記「未在檔案中找到」。

這條直接延伸自本專案先前那個 Critical 的教訓:「修改既有軌道」對話框曾靜默丟掉使用者設定,結果用假的保證重現了它本來要防的災難。**掃描結果只能是資訊,不能拿來替使用者做刪除決定。**

### 3. 主表格新增「預計 / 結果」欄

執行前顯示預告(例:`Default 48 → 54`),執行後就地換成結果。

**適用範圍:** 字幕檔與封裝分頁有完整的「預計 → 結果」。MKV 分頁因不做逐檔解析(見第 5 節),該欄只在執行後顯示結果。

**不需要新演算法**:`compute_applied_values()` 本來就會依 PlayRes 算出實際套用值,與該檔目標樣式的現值一比即得。縮放模式的 `scale_text` 也已回傳變更報告。定義一個共同的「預計變更」資料形狀,讓兩種模式都轉成同一種欄位文字;該轉換函式放純邏輯層。

**狀態轉換:** 執行中顯示「處理中…」,完成換結果,重新掃描回到預告。不可讓上一輪結果留著被誤認成這次的。

### 4. 開啟時自動掃描目前顯示的分頁

只掃當下顯示的那一個分頁;切到其他分頁時才掃那一個,且每個分頁只掃一次。

理由:掃描會對每個配對到的影片跑一次 ffprobe 子行程,一季 24 集約 1–5 秒。開啟時三個分頁全掃,等於為使用者沒要看的分頁白跑子行程。

### 5. 各分頁的解析成本差異(關鍵取捨)

**字幕檔 / 封裝分頁**:字幕是外部 `.ass`,解析是毫秒級。全部解析,樣式清單與逐檔預告都做。

**MKV 分頁**:字幕在 mkv 檔內,讀樣式名須先 `mkvextract`。一季全抽很慢,且 2026-07-27 的 UI 重整才刻意移除遞迴 `mkvmerge -J` 就是嫌慢。

因此 MKV 分頁的樣式清單改為**按需從「範本檔」讀取**:使用者按「讀取樣式名稱」,只抽第一個檔案的一條字幕軌來讀。這呼應該分頁既有的心智模型(「修改既有軌道」對話框本來就是上半在範本檔上定規則、下半逐檔驗證)。

代價:MKV 分頁**沒有逐檔預告欄**,只有執行後的結果欄。使用者情境為「全季一致」,只讀一個範本檔已足夠。

## 元件

### 新增

**`ass_style_tool/style_scan.py`(純邏輯,不依賴 Qt)**
- `scan_styles(path)` — 讀一個字幕檔,回傳其中的樣式名、各樣式現有字級、該檔 PlayRes
- 彙整函式 — 把整批結果併成排序去重的樣式名清單,並回報不一致的檔案

放純邏輯層是為了能直接用真實 `.ass` 檔測試,不必開 Qt。

**`ass_style_tool/qt/style_picker.py`** — 側欄可勾選清單元件。對外介面僅「目前勾了哪些」與一個 `changed` 訊號。

### 擴充既有

`MatchResult` 增加樣式名、PlayRes、解析失敗時的錯誤字串。`scan_folder()` 在現有的檔名配對與 ffprobe 之後多跑一輪解析。封裝分頁走自己的 `pair_for_mux`,同樣呼叫 `scan_styles` 共用原語。

`style_editor.py` 移除「目標 Style」欄位,但保留讀寫 profile 該鍵的能力以維持相容。

## 錯誤處理與邊界

- **壞檔**:單檔解析失敗記錄錯誤字串、掃描繼續,該列標記「無法讀取」但仍列出。沿用既有 `batch_runner` 單檔失敗不中斷的作法。
- **編碼**:走既有 `detect_and_decode`(已處理 UTF-8 / Big5 / GBK 判別),不重寫第二套。
- **勾選為空**:執行鈕停用並說明原因,而非跑完一輪才發現全部 skipped。
- **資料夾已不存在**:不觸發掃描、清單留空並說明,但**不清掉路徑文字**(可能只是外接硬碟沒插)。
- **MKV 範本檔抽不到文字字幕軌**(整批 PGS/VobSub 圖形字幕):明確說明「這批沒有文字字幕軌」,不給空清單讓使用者猜。
- **掃描中切換分頁**:沿用既有分頁的 `_thread` 狀態守衛,避免重複觸發或掃描中重啟。

### 一併補上的既有缺口:掃描可取消

`ScanWorker` 目前沒有取消機制,`scan_folder()` 一旦開始就得跑完。以前掃描是使用者主動按的,影響有限;改成自動掃描後,誤指到有數百個檔案的資料夾會讓使用者被卡著只能等,而新增的樣式解析又讓掃描更慢。

補上掃描的進度回報與取消(檔案之間檢查旗標),作法與 `BatchWorker` 既有機制一致。這是自動掃描這個改動誘發出來的問題,不是無關的重構。

## 測試策略

沿用專案既有分層:純邏輯層用真實檔案測,Qt 層 offscreen 測,外部工具一律注入假物件絕不真的呼叫。

**純邏輯層(`style_scan.py`)**:在 `tmp_path` 寫出不同 PlayRes、不同樣式名組合、Big5 編碼、故意壞掉的檔案,驗證解析結果與彙整邏輯(去重、排序、不一致偵測)。

**預告文字轉換**:單獨測兩種模式(套用樣式 / 縮放字級)、找不到目標樣式、壞檔各自的輸出。

**Qt 層**:測 picker 勾選行為,以及三個分頁的自動掃描規則——只觸發一次、切走再切回不重掃、掃描進行中不重複觸發、資料夾不存在時不掃、勾選為空時執行鈕停用。

### 須用 mutation 驗證的兩條

依專案既有教訓「宣稱在守某個約束的測試,要用 mutation 驗證它真的會失敗」,以下兩條實際跑兩輪(先改壞確認測試變紅,再改回確認變綠):

1. **不自動取消勾選**——把「保留未找到的名稱」改成「掃描後過濾掉」,測試必須紅。這是整個設計最重要的不變式。
2. **掃描可取消**——把取消旗標檢查拿掉,測試必須紅(壞接線會把全部檔案跑完,正確接線會中途停)。

### 不做

- 不真的執行 mkvextract / ffprobe
- 不做 GUI 截圖比對
